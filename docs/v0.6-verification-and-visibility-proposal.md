# Lattice v0.6 — Verification & Visibility

Document status: design proposal, ready for review
Driver: the v0.5 release added the BRD axis (business intent) but
adoption stops at *declaration*. v0.6 closes the loop so a human (or
AI agent) can answer the three questions Lattice claims to:

1. **What does this system do, business and technically?**
2. **What interactions does it support?**
3. **Is what's implemented what was required?**

---

## 1. The gaps v0.6 closes

| Question | Today | After v0.6 |
|---|---|---|
| "Is BRD X actually verified?" | No answer — `maps_to_invariant` exists but nothing fails when a SC has no backing invariant | `/rtm` answers per-SC + per-BRD; `BRD_CRITERION_UNVERIFIED` warning; 5th Coverage card |
| "Show me the refund flow" | Reconstruct from 12 EP pages | `/journeys/brd.checkout.refund` aggregates every EP that touches a feature implementing the BRD |
| "What can a Merchant do here?" | Read context.yaml + grep EPs | `/actors/merchant` lists touchpoints with one click |
| "AI agent: tell me what's unverified" | No MCP tool surfaces this | `list_unverified_criteria()` returns structured JSON |
| "Find features about refunds" (no keyword overlap) | Keyword search only | `/search?semantic=1` over BRD + EP prose |

## 2. Three streams

### α. Requirements Traceability Matrix (RTM)

For each BRD success_criterion with `maps_to_invariant: <feature.id>:<INV-N>`:

| Walk | Source |
|---|---|
| SC → invariant | feature manifest |
| invariant → enforcer(s) | `Symbol.EnforcesInvariants` (graph) |
| invariant → verifier(s) | `Test.Verifies` (graph) |
| invariant → mutation score | `mutation-scores.json` if present |

Per-SC status:

- **VERIFIED** — invariant exists, enforcer + verifier present, mutation ≥ threshold (or unset)
- **PARTIAL** — enforcer + verifier present, mutation below threshold
- **UNENFORCED** — invariant exists but no enforcer
- **UNVERIFIED** — invariant exists but no verifier
- **PHANTOM** — `maps_to_invariant` names a non-existent invariant
- **UNMAPPED** — SC has no `maps_to_invariant` at all

New validation rules:

- `BRD_CRITERION_PHANTOM_INVARIANT` — error
- `BRD_CRITERION_UNVERIFIED` — warning (covers all of UNENFORCED / UNVERIFIED / PARTIAL — one rule, message includes which)
- `BRD_CRITERION_UNMAPPED` — info

5th Coverage card: **BRD goal coverage** = `verified SCs / total SCs`.

**No schema changes.** Walks existing `maps_to_invariant` field.

### β. Journey view

`/journeys/{brd-id}` — every EP whose flow visits a feature in
`brd.implements_via`. Mermaid graph of `EP → feature → feature ...`.
Grouped by EP kind (HTTP / CLI / cron / queue) when the BRD's
`user_scenarios` doesn't link explicitly.

`/actors/{actor-id}` — read context.yaml actors, list EPs they
`uses`, with feature touchpoints. Read-only.

### γ. Agent query surface

MCP tools added:

- `get_journey(brd_id)` — full journey JSON (EPs, features, flow steps)
- `verify_brd(brd_id)` — RTM rows for one BRD + roll-up
- `list_unverified_criteria()` — every SC not in VERIFIED state
- `list_actor_touchpoints(actor_id)` — same shape as `/actors/{id}`
- `semantic_search(query)` — over BRD + EP prose

Plus `/search?semantic=1` for the UI. Embeddings cached under
`lattice/.cache/embeddings/` so re-runs are cheap.

## 3. Out of scope (for v0.6)

- **Test result ingestion.** The RTM shows *declared* verification
  (enforcer + verifier exist). Whether the verifier *passes* on the
  current commit is a v0.7 concern (junit/phpunit/pytest XML →
  graph). Calling it out so we don't promise more than α delivers.
- **BRD goal → SC linkage.** Goals stay `[]string`; SCs are verified
  individually. We may add `BRDCriterion.implements_goal` later.
- **Test result history / trends.** Snapshot only.
